# 3DGS 算法与算子测试设计

面向算法测试、算子测试和性能测试工程师。目标是建立一套能够回答“数学是否正确、梯度是否正确、训练是否有效、加速是否可信、长期运行是否可靠”的测试体系。只检查输出 shape、无 NaN 或最终 PSNR，均不足以证明 3DGS 正确。

本文先确定十二章框架，再按框架展开。**测试方案和建议门槛不等于已经执行的测试结果。** 本次工作完成源码审查、公开资料核对和一次 CPU 测试尝试，没有执行 NPU 算子、完整训练或性能测量。执行记录见第 10 节。

阅读路径：项目负责人先读第 1、10、11 节；算子工程师读第 2—6 节；算法与性能工程师读第 7—9 节。基础概念见[入门篇](3dgs_beginner_guide.md)。

### 1.2 范围划分

主范围：静态场景、RGB 训练与渲染、当前高斯参数化、投影/筛选/相交/排序/调度/混合的正反向、SSIM、曝光、融合 Adam、密度控制、模型保存加载，以及 A2/A3—A5 迁移。

### 1.3 三类证据必须分开

**源码事实**是实际看到的布局、参数、分支、分配和测试断言；**审查风险**是这些事实可能导致的失败，需最小复现验证；**测试设计**是本文提出的输入、参考和门槛。没有运行结果的风险不标记成已复现 bug，也不能因为存在测试文件就标记该能力已通过。
## 2 代码框架与调用链

### 2.1 分层架构

| 层 | 当前 G 源码 | 测试责任 |
| --- | --- | --- |
| 数据与配置 | `examples/datasets/{colmap,normalize}.py`、`examples/rasterization/config.py` | 图像和相机对应、缩放、数据划分、配置实际生效 |
| 训练引擎 | `examples/train.py`、`examples/rasterization/{runner,utils}.py` | 初始化、loss、更新顺序、指标、保存与加载 |
| 密度控制 | `examples/gsplat/strategy/{default,adc,densify,ops}.py` | 复制、分裂、删除及参数/优化器同步 |
| 渲染编排 | `gauss_splat/ops/rendering.py` | 激活、相机分派、流水连接、重排和缓存 |
| Autograd 包装 | `gauss_splat/ops/` | 前后向对应、输出梯度、布局转换、缓存生命周期 |
| C++ 绑定 | `gauss_splat/csrc/{pybind,functions,...}` | ABI、dtype/shape/device、分配、符号及 ACLNN 调用 |
| Host 与设备 | `kernels/<op>/op_host/<arch>`、`op_kernel/<arch>` | tiling、分核、尾块、UB/GM 搬运、同步与数值实现 |
| 现有测试 | `tests/host`、`tests/ops`、`tests/kernels` | 主机逻辑、Python 接口、ACLNN 层；覆盖强度须另审 |

路径均相对 G。历史 R 对应入口为 `3d_vision/gaussian_splatting/rasterization/rasterizer.py`，算子包是 `ops/ascendc/meta_gauss_render`。两套包、二进制和测试不要混装。

### 2.2 当前前向主链

```text
Runner / Rasterizer.rasterization
  ├─ scales.exp、opacities.sigmoid、camtoworlds 求逆
  ├─ sh_preprocess → spherical_harmonics → 加0.5与非负截断
  ├─ projection_three_dims_gaussian_fused
  │    ├─ quat_scales_to_covars（取决于融合开关）
  │    ├─ projection_three_dims_gaussian_forward
  │    └─ gaussian_filter：压缩属性、计数、原始ID/掩码
  ├─ flash_gaussian_build_mask：高斯与Tile配对
  ├─ CPU get_render_schedule_cpp：按负载安排Tile
  ├─ gaussian_sort：Tile内按直接深度z排序
  ├─ calc_render：RGB和传入深度属性的加权合成
  └─ tile2image：重排、裁去padding
```

`rendering.py` 当前在混合前把深度转为逆深度；相交及排序仍使用直接深度 z。相交、调度和排序处于 `no_grad` 内，它们产生离散拓扑，不能按普通连续函数要求其对参数可微。

多相机 C>1 在 Python 层逐视角调用，每个视角创建独立 `RastCtx`，再拼接输出。它不是一次底层 kernel 完成所有相机的并行渲染。性能报告必须注明这一点。

### 2.3 反向链与架构分支

图像 loss → `CalcRender.backward` → 屏幕中心/conic/opacity/color/depth 梯度 → 投影融合反向与 SH 反向 → 高斯原始参数。原始尺度和 logit 还经过 exp/sigmoid 链式求导。来自多个 Tile、像素和相机的同一高斯梯度要正确累加。

| 项目 | arch22 / A2/A3 | arch35 / A5 | 必测差异 |
| --- | --- | --- | --- |
| 渲染后端 | `clip_gsids` | `clip_lastids` | 保存中间态不同，前后向语义必须配套 |
| 投影参数梯度 | kernel 为 N-first，包装转置 | channel-first | shape 相同不能代替元素对应检查 |
| 反向压缩 | 使用原始参数和筛选信息路径 | 压缩参数、`dense_indices` 路径 | scatter 回原始 ID、不可见点梯度 |
| Render 像素块 | 按该后端契约 | Host 固定每 Tile 1024 像素 | A5 首先以 tile=32 验证，其他值需拒绝/另实现 |
| 训练 SSIM | `SSIM.ssim`，window=7、sigma=1.5 | `fused_ssim`，window=11、默认 sigma=0.75 | 当前训练目标不同，不能直接归因于硬件精度 |

具体分支见 `calc_render.py`、`rast_ctx.py`、投影封装和 `runner.py`。曝光与融合 Adam 属于扩展模块，需要纳入算子清单；存在实现不代表每个训练配置都会调用它们。
### 2.4 分层测试责任与证据边界

本节新增内容仅依据 `<gauss-splat-checkout>` 当前代码，不引用早期仓库实现推断当前行为。以下是测试设计与静态审查所得事实，尚未作为 NPU 测试执行。Python 封装、C++ 桥接、Ascend C Host 与设备内核是同一算子的不同职责层，不能把某一层通过当成整条调用链通过。

| 层级 | 必查重点 | 推荐输入与检查方式 | 应留下的证据 |
| --- | --- | --- | --- |
| Python 渲染编排 | exp/sigmoid、相机变换、SH 阶数、深度语义、相机循环、Tile 重排 | 不对称且逐项可辨识的小张量；逐阶段比较参考值；非 Tile 整倍数图像 | 激活后参数、相机矩阵、排序前后深度、最终裁边结果 |
| Python Autograd 封装 | 拼接/转置/连续化、可选输入、输出顺序、反向梯度槽位、保存张量生命周期 | RGB 与带深度两分支；重复前反向；受支持的多图并存；非连续输入 | 送入绑定层的真实张量、saved tensors、各输入梯度 |
| C++ 桥接 | dtype/shape/device/stride 契约、输出分配、属性及实参顺序、错误传播 | 直接调用绑定入口；一次仅破坏一项契约；对合法输入核对全部输出元数据 | 实际加载的扩展路径/架构、参数签名、错误位置、输出初始化 |
| Ascend C Host tiling | 形状约束、分核数、尾块、资源预算、tiling key、workspace、整数范围 | 临界尺寸前后、零任务、核数边界；大维度用元数据测试避免真实巨额分配 | 序列化 tiling 数据、blockDim、workspace、拒绝状态 |
| Ascend C 设备内核 | 数学公式、截断/早停、分核覆盖、GM/片上搬运、同步、越界、梯度累加 | 单高斯解析例、多高斯遮挡、空 Tile、不均负载、尾批与压力重复 | 逐元素误差、保护区/内存检查、运行时错误、性能与峰值内存 |
| 跨层集成 | 所有层支持范围一致、前后向配套、设备/流上下文、二进制版本配套 | Python→绑定→ACLNN 全链；与直接绑定/底层调用回放比较 | 同一输入下各边界快照、最早差异位置、完整环境记录 |

“职责”不代表当前代码已对每种非法输入做充分校验。例如 [CalcRenderClipLastids.cpp](https://github.com/Atlas-Ascend-Fork/gauss-splat/blob/25c6e337761ad2414a6d3377415681d229fe7a3b/gauss_splat/csrc/CalcRenderClipLastids.cpp) 检查连续性，而 [ShPreprocessBwd.cpp](https://github.com/Atlas-Ascend-Fork/gauss-splat/blob/25c6e337761ad2414a6d3377415681d229fe7a3b/gauss_splat/csrc/ShPreprocessBwd.cpp) 会主动 `.contiguous()`；测试必须按实际入口区分“应拒绝”和“应转换”，不能统一要求所有算子拒绝非连续输入。

同样，Host/设备实现的精度与性能标准应按具体架构制定；不能因为同名 Python 函数就假设两种架构的内核、缓存或输出梯度布局一致。算子细项见第 5、6 章；策略参数变化后的集成见 DC14—DC18。

### 2.5 当前代码对应的分层用例

#### LY01 Python 属性打包与梯度拆包（P0）

- **输入**：N=3，二维中心、三个 conic 分量、opacity、RGB、depth 各填不同数值，确保列交换可识别；sorted IDs 使用合法整数类型；分别提供 depth 和 None。
- **步骤**：对 [CalcRender](https://github.com/Atlas-Ascend-Fork/gauss-splat/blob/25c6e337761ad2414a6d3377415681d229fe7a3b/gauss_splat/ops/calc_render.py) 的绑定调用做记录桩，捕获传入 gs 和 ID；让反向桩返回每列唯一的 `[N,10]` 梯度；检查 Python 返回给各输入的梯度。再在 NPU 上替换为真实后端完成集成验证。
- **预期结果**：gs 连续且为 `[N,10]`，列依次是中心 2、conic 3、opacity 1、RGB 3、深度属性 1；ID 转为 int64。无 depth 时最后一列用颜色第一通道占位，但接口只返回颜色且不返回 depth 输入梯度；反向各列严格映射回原输入，无错轴或错槽。桩测试仅证明封装接线，不证明内核数学正确。

#### LY02 C++ 元数据与非法输入（P0）

- **输入**：A5 clip_lastids 合法 NPU FP32 gs `[N,10]`、coords `[T,2,1024]`、合法 int64 offsets/IDs；逐次改为错误 dtype、CPU 张量、混合设备、非连续布局、gs 属性维 9、coords 坐标维 3。
- **步骤**：绕过 Python `CalcRender` 直接调用已加载的 `_C.calc_render_fwd_clip_last_ids`；记录异常与输出。多设备用例仅在具备至少两张设备时执行，缺少条件标记跳过。合法输出继续送入配套反向。
- **预期结果**：合法输出 color `[3,T,1024]`、depth/lastCumsum/error/lastIds `[T,1024]`，lastIds 为 int32，其余 FP32，设备一致；对应源码已有检查的非法项在桥接拒绝。反向 vDepth 需 `[1,T,1024]`，不能误传前向 depth 的二维布局。没有校验的值域问题另立缺陷，不能据元数据检查推出 IDs 一定合法。

#### LY03 桥接与 Host 支持范围一致性（P0）

- **输入**：同 LY02，分别使用 `P=0,1,1023,1024,1025`，其余 shape 与 P 配套。
- **步骤**：记录桥接检查结果与 Host tiling 结果；在 Host 测试夹具独立回放同一元数据；全链测试捕获运行时失败。
- **预期结果（当前源码）**：桥接接受 `1<=P<=1024`，但 [Host tiling](https://github.com/Atlas-Ascend-Fork/gauss-splat/blob/25c6e337761ad2414a6d3377415681d229fe7a3b/kernels/calc_render_fwd_clip_last_ids/op_host/arch35/calc_render_fwd_clip_last_ids_tiling.cpp) 要求 `P=1024`，所以全链有效值仅 1024。0、1025 应被桥接拒绝，1、1023 应在后续 Host 被拒绝，不得静默按另一尺寸计算。这一分层校验不一致需要登记，推荐统一最外层契约；在修复前不能把“桥接通过”报告成该尺寸受支持。

#### LY04 连续化行为按接口区分（P1）

- **输入**：用步长切片构造内容相同但不连续的张量；分别满足 CalcRenderClipLastids 和 ShPreprocessBwd 的其他契约。
- **步骤**：直接调用两种 C++ 入口，与连续副本比较；不要经过会提前 `.contiguous()` 的 Python 包装来测试桥接拒绝能力。
- **预期结果**：CalcRenderClipLastids 入口拒绝非连续输入；ShPreprocessBwd 按当前源码转换连续输入并返回与连续副本一致的结果。若走 Python 的输入已被规范化，应记录为上层转换成功，不得宣称底层支持任意 stride。

#### LY05 分核、尾批与写回完整性（P0）

- **输入**：当前内核固定 P=1024；设实际调度核数为 B，Tile 数取 `1,B-1,B,B+1,2B+1`（剔除无效/重复项）；每 Tile 的高斯列表长度覆盖实际批容量前后，并包含空列表和极不均负载。
- **步骤**：依据当前 Host 实际输出读取 B 与批容量，不硬编码猜测；逐 Tile 使用独立混合参考；在底层测试允许时预填输出标记，检查所有合法输出写回；开启可用内存检查并重复运行。
- **预期结果**：每个有效 Tile 被正确处理，无漏算、错位、重复写冲突和尾批越界；空列表按定义输出；中间态也符合前反向契约。哨兵或保护区检查必须由支持该缓冲管理的测试入口完成，不能声称仅调用 Python 就检查了底层全部写界。

#### LY06 前向中间态与反向后端配套（P0）

- **输入**：同一合法小场景，已确认实际构建选择 clip_lastids 或 clip_gsids；固定上游 color/depth 梯度。
- **步骤**：分别捕获 Python 前向保存状态和直接绑定前向返回状态，回放相同后端反向；比较 vGs，再比较 Python 拆出的各输入梯度；重复执行两次不同输入以探测缓存污染。
- **预期结果**：同一后端的回放结果按精度协议一致；clip_lastids 的 lastIds 与 clip_gsids 的 gs_clip/alpha_clip 不混用。若 Python 梯度错而 vGs 正确，优先检查拆包；若两者均错，继续检查反向内核及保存态，而不能直接归咎于 Autograd。

### 2.6 跨层问题定位流程

按“同一份输入、逐层回放、找到最早差异”定位，避免不同随机输入或参数布局造成假结论。

1. **冻结环境与语义。** 记录本仓库提交、加载的扩展绝对路径、构建架构、torch/torch_npu/CANN 版本、设备、种子、shape/dtype/stride、相机、Tile 大小和深度定义。先排除运行了旧 wheel、错误架构产物或错误设备。
2. **缩小失败样例。** 保留最少的高斯、Tile、相机和反向分支；性能/并发故障仍保留触发规模。记录“只在某个尺寸失败”等边界，不因缩小后消失就认定修复。
3. **捕获 Python 到绑定层的实际输入。** 包括激活后的尺度/alpha、压紧 ID、gs 属性列、offsets 和排序结果。保存数值而不只保存 shape，与独立参考比较。
4. **直接调用绑定回放。** 用完全相同的输入调用 `_C`，比较全部输出和反向状态。若直接调用正确但完整流程错误，检查 Python 预处理、后处理、缓存和梯度映射；直接调用也错仍不能单凭此区分桥接与内核。
5. **核对桥接、Host 与底层契约。** 对照 C++ 实参顺序、输出分配和 ACLNN 参数；在对应 `tests/kernels` 入口或最小 ACLNN 测试程序回放相同数据。检查 Host 的分核、固定维和资源计算。底层回放必须使用同一二进制、同一输入和等价同步条件。
6. **比较设备结果。** 以独立参考检查第一个出错的算子；对反向从固定输出梯度开始，逐段检查 vGs、投影梯度、SH 梯度和最终参数梯度。只有维持相同离散分支时才使用光滑差分结论。
7. **检查异步与共享状态。** 设备错误可能延迟到后续 API 才报告；在诊断模式下于可疑边界同步以定位，记录同步对时序的影响。普通回放成功但并发失败时，检查流、buffer 生命周期与覆盖，而非只重复数学精度测试。
8. **双层回归。** 修复后同时回归定位出的最小层用例与原始端到端失败样例；涉及性能时移除诊断同步再测。报告首个差异边界和根因证据，而不是“最后报错的层”。

| 现象 | 优先检查 | 进一步确认方式 |
| --- | --- | --- |
| 整幅图颜色/位置系统性错误 | Python 相机、属性布局、激活与重排 | 比较入绑定层数值及独立数学参考 |
| 只在 P 不等于 1024 时失败 | 桥接与 Host 固定维契约 | 执行 LY03，分别记录两层结果 |
| 尾部点/Tile 错，整倍数正常 | Host 分核与内核尾批 | 执行 LY05，比较分核范围与漏写位置 |
| 前向通过，梯度错 | 保存态、反向形状、梯度拆包、累加 | 执行 LY06；以固定上游梯度分段回放 |
| 单次通过，连续或并发失败 | 上下文、缓存、流与复用缓冲 | 对比序列化和多图测试，保留现场输入 |
| 计算正确但整体很慢 | Python 循环、同步、分配与设备执行 | 分开测端到端和设备时间，不用 kernel 时间代表完整训练吞吐 |

这些现象只提供排查顺序，不构成根因证明。CPU 桩、Host 单测、NPU 算子和端到端测试的结论必须分别记录，特别不能把不经过真实设备的测试算作 Ascend C 正确性证据。

## 3 接口与数值语义契约

### 3.1 先冻结契约，再生成 golden

定义 N 为原始高斯数、C 为相机数、B 为底层批次、T 为 Tile 数、L 为有效高斯—Tile 配对总数、K 为 SH 基函数数。高层主链当前固定 B=1。

| 数据 | 当前高层主入口 | 约定与验证 |
| --- | --- | --- |
| means / quats | `[3,N]` / `[4,N]` | FP32 主路径；四元数次序和归一化须用单位旋转及轴旋转确认 |
| scales / opacities | `[3,N]` / `[N]` | 高层分别为 log-scale/logit；低层投影接收激活后的值 |
| SH | `sh=[K,3,N]` | active degree 对应 `(degree+1)^2≤K`；检查未激活系数梯度 |
| 相机 | c2w `[C,4,4]`，K `[C,3,3]` | 内参矩阵 K 与 SH 基函数数 K 是不同概念；测试实现中建议分别命名 Ks、n_sh |
| 图像尺寸 | `(width,height)` | 输出为 `[C,H,W,3]`，避免 H/W 对调 |
| 投影中心与 conic | `[B,C,2,N]` / `[B,C,3,N]` | 压缩后仅前 cnt 项有效，其余容量不能直接作为有效结果比较 |
| Tile 配对 | count、offset、depth、ID | count/offset/ID 精确判定；当前配对 ID 中间存储有 FP32 |
| 最终深度 | `[C,H,W,1]` | 当前主链累积逆深度；模式名称尚不足以证明 D/ED 语义 |

`README.md` 示例仍使用 N-first、`sh0/shN`，而实际入口读取 channel-first 与 `sh`。测试夹具优先依据源码构造，再把文档与实现差异登记。checkpoint 又使用 N-first 保存，加载时迁移 `sh0/shN` 并转换布局；运行态与存储态不可混淆。

外部参考使用 wxyz 四元数及 w2c view matrix，但必须显式适配，不能因函数名相近直接替换。[gsplat 坐标约定](https://docs.gsplat.studio/main/conventions/data_conventions.html)

### 3.2 数值分支是接口的一部分

冻结以下项目：像素中心位置、二维协方差正则项 eps、视锥边界是否包含、有效半径规则、alpha 上限与下限、相交判据、深度相等的排序策略、背景、早停时是否累加触发项、深度属性、SH 颜色截断、各架构补偿开关。

当前 A5 `fwd_simt_vf.h` 的 alpha 上限为 0.999、贡献下限为 1/255；若 `nextT≤1e-4`，进入 done 分支，**该次不累加颜色和深度，但更新透射率状态**。参考实现应逐条复现；不能只把“提前停止”四个字当成完整定义。A2/A3 另冻结实际分块剪枝规则，不默认两架构离散边界完全相同。

深度最小例：一个高斯在 z=2、像素 alpha=0.5、黑背景，累积 z 是 1，期望 z 是 2，累积 1/z 是 0.25。当前主链输出用于该属性的期望值为 0.25。外部 D/ED 定义见 [gsplat rasterization](https://docs.gsplat.studio/main/apis/rasterization.html)。

### 3.3 支持范围表必须可检查

为每个层级建立 capability manifest，字段至少包括架构、API、dtype、布局、是否连续、N/C/Tile 范围、可选输入、可微输入/输出、空输入、原地写入、线程与 stream 限制。未知项写 `unverified`；仅通过字符串校验的参数不能写 `supported`。FP16/BF16、不支持的相机和二阶求导首先验证清晰拒绝，而非假定全部可运行。

### 4.1 测试金字塔

| 层级 | 对象 | 参考与交付物 | 典型频率 |
| --- | --- | --- | --- |
| L0 | 构建、导入、契约、配置接线 | 接口清单、异常断言、最小 forward/backward | 每次提交 |
| L1 | 数学原语、单算子 | 手算、CPU FP64、自动微分、精确索引集合 | 每次相关变更 |
| L2 | 融合流水、缓存、一次参数更新 | 中间张量对照和固定拓扑 | 每次提交的小集 |
| L3 | 短训练、增密、保存加载 | 曲线、结构状态和固定 checkpoint | 每夜 |
| L4 | 完整多场景质量 | 保留视角、多个 seed、伪影检查 | 发布前 |
| L5 | 性能、容量、兼容与长稳 | profiler、延迟分布、内存曲线、平台矩阵 | 专项及发布前 |

### 4.2 三种参考不能互相替代

1. **数学参考**：CPU FP64 实现协方差、投影、SH 和无剪枝 alpha 合成；用于验证公式与衡量近似误差。
2. **同语义参考**：在 CPU 中显式实现该后端阈值、排序、早停和布局；用于判断设备实现是否正确。
3. **独立交叉参考**：固定版本的 Graphdeco 或 gsplat；完成语义对齐后验证图像与训练趋势。

高精度只减少舍入误差，不能修复错误算法。参考代码应以不同方式表达，例如设备按解析梯度实现，CPU 用自动微分；筛选 kernel 用专用近似，参考用明确几何优化。gsplat 也采用原生 PyTorch 与设备实现对照的测试方式。[gsplat 测试文档](https://docs.gsplat.studio/main/tests/tests.html)

### 4.3 精度标准建议

对有效域浮点输出，按元素检查 `|y-ref|≤atol+rtol*|ref|`，同时记录最大绝对误差、P99 误差、归一化 L2、超限元素数及其坐标。参考为零的梯度用绝对误差，不能让相对误差除零或掩盖符号错误。

| 对象 | 建议初始门槛 | 使用条件 |
| --- | --- | --- |
| ID、掩码、count、offset | 精确相等或规范化后的集合精确一致 | 不用浮点相对误差比较整数 |
| 适度尺度 FP32 原语 | atol=1e-5，rtol=1e-4 | 远离奇异点与阈值；逐张量确认单位 |
| 平滑区 FP32 梯度 | atol=1e-4，rtol=1e-3 | 与 FP64 自动微分比较；多项累加单独分桶 |
| 图像融合同语义小例 | atol=1e-4，rtol=1e-3 | 拓扑、排序、阈值一致 |
| 病态/长归约输入 | 按条件数与累加长度单独标定 | 不能放宽一个全局阈值让所有输入通过 |

这些数值是建立测试的起点，不是论文标准或承诺。先用独立参考测量稳定误差，再冻结每个算子、架构和输入桶的预算；预算变更需要理由和旧新结果。NaN/Inf、错 ID、梯度缺失和符号错误不能用放宽门槛解决。

### 4.4 测试数据生成

数学小例使用 N=0、1、2、3、7、8、9、31、32、33、255、256、257 等规模，覆盖空输入、位图尾字节、向量与分块尾部。图像使用 1×1、31×33、32×32、33×65、63×64 等非方形尺寸；负尺寸是异常用例。只在实际支持的 Tile 下验证成功路径。

构造球形、细长、扁平、旋转椭球；可见率 0/1/50/100%；单一热点与均匀负载；唯一深度和相同深度；极小/普通/极大透明度。随机数据记录 seed，并混入解析可判定样本。设备大规模压力只在第 9 节容量预算检查后运行。

Golden 包至少保存输入、版本/配置、有效数量与 ID、关键中间量、输出、上游梯度、参数梯度、容差版本及哈希。遇到失败先最小化 N、视角和像素区域，再调查。

### 5.2 一个可手算的投影测试

令世界到相机为单位变换，$\mu=(0,0,2)$，s=(0.1,0.2,0.3)，q 为单位旋转，fx=fy=100，cx=cy=16，eps=0.3。理论中心为 (16,16)，z=2；在中心处 J 的前两项为50，得：

$$\Sigma_{2D}=\operatorname{diag}(25,100)+0.3I=\operatorname{diag}(25.3,100.3).$$

conic 对角为 $1/25.3$ 和 $1/100.3$，交叉项为0。这个用例能区分“尺度忘记平方”“焦距/深度比例错”“eps加错位置”。半径取整和筛选阈值另按实现断言。

### 5.3 精确相交参考怎样做

对 SPD conic Q，矩形 Tile 区域内最小化 $f(p)=(p-\mu)^TQ(p-\mu)$。如果中心在矩形内，最小值为0；否则对四条边分别求一维二次函数的极小点并截到边界，连同端点取最小值。与由贡献下限得到的阈值 $2\log(o/\alpha_{min})$ 比较，构造连续区域相交参考。

该判据建立在正定 Q、有效 opacity 和对应贡献阈值上。离散像素中心集合、连续矩形、包围盒是不同支持域；如果 kernel 使用保守扩张，要分别报告误纳和漏纳。误纳主要多做计算，漏纳可能丢失有效贡献。不能未经说明把像素暴力枚举当成连续矩形相交的绝对真值。

边界样本先构造相切点，再在法向两侧扰动；对非常接近阈值的浮点点使用区间/双精度复核，并保留“数值边界桶”。FlashGS 的冗余消除提供这一类测试的背景，而不是具体项目的验收标准。[FlashGS](https://maxwellf1.github.io/flashgs_page/)

### 5.4 排序相等键与调度

深度相等时，红蓝不透明度混合仍可能受 tie 顺序影响。若接口承诺稳定排序，精确检查原始次序；若未承诺，先确认目标契约，按合法 tie 策略生成参考，不能简单将全部序列排序后忽略遮挡差异。优先用唯一深度定位普通排序错误，再专门测试 tie。

调度不是只看负载是否平均：确认每个 Tile 被分配一次，调度顺序改变不改变它对应的输出位置与排序片段；检查零工作、核数大于 T、极不均匀工作量、int32 累加边界。不同有效调度可以接受，但必须满足相同的不变量。

### 5.5 扩展算子与框架算子

| 用例组 | 覆盖 | 断言 |
| --- | --- | --- |
| OP13 FusedSSIM | window=7/11/15，sigma，B/C/H/W尾部；常量图、相同图、单像素脉冲 | 对照卷积参考的整张SSIM map和reduction；完全一致图约为1；边界padding相同 |
| OP14 Exposure | 全局和网格模式、网格角点/边缘、越界、clamp | 恒等变换保持颜色；三线性权重、索引和边界处理精确；颜色与曝光梯度分开 |

| OP16 激活与基础接线 | exp/sigmoid、拼接、转置、gather/scatter、inverse | 单独数学检查后验证融合接线；非连续张量、dtype与device错误 |

`fused_ssim` 的 reduction=`none` 返回每张图的平均值 `[B]`，不是完整 map；底层 `FusedSSIM.apply` 返回 map。测试两层时要使用各自契约。sigma 与窗口必须一致，不能只对齐窗口。

### 5.6 接口异常与内存安全

逐算子注入 shape/dtype 不匹配、CPU/NPU 混合、不同 NPU 设备、非连续 stride、越界 ID、错误 count、过小输出容量、NaN/Inf。合法非连续输入若包装主动 `.contiguous()` 应成功；低层不支持则明确拒绝。错误路径应包含可定位信息，不应静默读越界、设备挂死或污染后续调用。

越界、超容量和设备故障类在独立进程并设超时，按目标 CANN 提供的工具做内存检查。对预分配输出用可识别哨兵填充，检查有效区是否完整写入、边界是否被破坏；无定义的尾部不要求全零，但不可被下游当成有效输入。

### 5.7 Ascend C分核与流水专项

算子测试要直接覆盖Host生成的tiling方案，避免所有数据都落在同一分支。先从各架构Host代码提取实际UB预算、每块容量、对齐粒度、最大张量数和分核规则，再生成“阈值减1、等于阈值、阈值加1”的输入；不要把某个硬件的分块常数当成全平台固定值。

| 专项 | 构造与检查 |
| --- | --- |
| 大小核与尾核 | N小于核数、恰好整除、仅尾核1个有效元素、对齐后少用核；确认有效覆盖区间并集恰好为输入域，无负长度、遗漏和重复 |
| 位图跨块 | 在7/8、15/16及实际每核分界两侧交替设置可见位；核边界与byte边界同时覆盖，压缩与反向还原均按原ID正确 |
| UB分块与GM偏移 | 1块、2块、3块以及最后不足一块；每块赋不同数据模式，检测跨块旧数据和错误读写偏移 |
| Double buffer | 奇数/偶数循环次数、最后一轮只部分有效；ping/pong缓冲填不同哨兵，检查预取、计算、写回事件先后及最后一次排空 |
| SIMD掩码与SIMT分歧 | 全有效、全无效、仅首/末lane有效、棋盘式有效；某像素很早done而相邻像素很晚done，二者不得互相影响 |
| Cube/Vector协作 | 若该分支采用混合核，覆盖两侧不同工作量与尾部；核间同步前不得消费未就绪中间结果 |
| Scatter/归约 | 多个Tile写同一高斯梯度；不同核碰撞强度递增；检查初始化、原子加与多轮复用 |
| Workspace | 最小合法容量、正常容量与独立实例复用；生命周期必须覆盖异步执行，不因Host函数返回提前复用 |
| Tiling与输出推导 | shape推导、数据类型、workspace大小、实际launch参数彼此一致；错误维度在launch前被拒绝 |

尤其是历史GaussianFilter资料给出了按8对齐的分核思想，测试应以当前Host源码中的实际尾核起点与长度验证，不直接抄资料公式作为golden。对每核区间`[start,end)`做主机侧不变量检查，能在设备运行前发现off-by-one和负长度问题。[历史筛选设计](https://gitcode.com/cann/cann-recipes-embodied-ai/blob/45d167135c81d97573bfbe0e564bb4a1d9642514/docs/3d_vision/gaussian_splatting/gaussian_splatting_culling_optimization.md)

流水测试需要在调试与发布构建各运行一遍关键小例。调试同步可能掩盖竞态；只在插入全局同步后正确，不等于发布路径正确。对原子归约的重复运行记录误差范围，允许经过论证的浮点归约波动，但不允许ID、count和状态漂移。
## 6 梯度与自动求导测试

### 6.1 为什么前向通过还不够

训练依赖 loss 对每个参数的导数。颜色可能正确，但某个尺度梯度漏乘2、跨Tile累加丢失、缓存复用了上一轮数据，都会造成收敛慢、增密失效或结果不稳定。

先对每一个支持的输入族单独求导，再做混合 loss：means、quats、log-scales、opacity-logits、SH、相机参数、曝光参数。协方差直接输入在包装反向中返回 None；radii/covars2d 的上游梯度未进入当前融合反向计算，不能默认这些输出均支持独立可微使用。架构相关 pose/K 梯度要逐分支验证，不沿用旧仓库的“全部 None”结论。

### 6.2 三重验证

**解析小例。** 黑背景单像素单高斯 $C=\alpha c$，未触发阈值时 $\partial C/\partial c=\alpha$、$\partial C/\partial\alpha=c$。两个高斯 $C=\alpha_1c_1+(1-\alpha_1)\alpha_2c_2$，则 $\partial C/\partial\alpha_1=c_1-\alpha_2c_2$。这些例子能捕捉透射率使用了前一项还是后一项。

**CPU FP64 自动微分。** 将待测输入转为 FP64，通过独立公式构造标量 loss；给输出非均匀随机上游权重，避免全1导致错误抵消。对比设备 VJP 的每个输入族，而非只比总梯度范数。

**方向有限差分。** 对固定方向 v，检查：

$$g^Tv\approx\frac{L(\theta+hv)-L(\theta-hv)}{2h}.$$

CPU FP64 可从相对尺度 h=1e-4、1e-5、1e-6 扫描稳定区；FP32 设备差分可从1e-2、1e-3、1e-4开始。不要因设备不支持FP64就强行套用双精度 gradcheck。优先验证同语义参考的导数，再用 FP32 设备输出与反向交叉检查。

### 6.3 离散边界的处理

裁剪、排序、半径取整、alpha阈值、颜色截断和早停都包含不光滑点。在平滑区梯度测试中，检查正负扰动前后可见 ID、配对、排序及早停位置不变；若变化则归入边界测试，不能直接判为解析梯度错。

边界测试验证实现选用的分段规则：阈值两侧、等于阈值、截断区域梯度、被剔除点梯度。四元数单位化、exp和sigmoid也要放进完整计算图：$\partial L/\partial\ell=(\partial L/\partial s)s$，$\partial L/\partial a=(\partial L/\partial o)o(1-o)$。

### 6.5 变形测试

将 q 替换为 -q，协方差和图像应相同；对不含额外约束的标量目标，相应四元数梯度应反号。移动场景和相机同样的世界平移，保持相对关系，应保图像。对唯一深度场景同步置换所有高斯属性，输出应不变、梯度按同一置换还原。将一批相机拆开执行，图像应相同、共享参数梯度应相加。

整体场景缩放的测试要同步缩放相机平移、高斯中心与尺度、near/far等具有长度单位的阈值；RGB在满足相同投影和筛选条件时保持，直接深度与逆深度按不同规律变化。若原始参数含log-scale，梯度转换必须按重参数化推导，不能要求所有梯度数值不变。
### 6.6 损失、反向传播与参数更新的具体用例

以下用例为新增测试设计，尚未执行，不属于已通过的 NPU 测试。基础算术和策略张量变换可在 CPU 验证；自定义算子反向、融合 Adam 以及 Runner 集成必须在对应 NPU 构建上验证。代码入口：[Runner](https://github.com/Atlas-Ascend-Fork/gauss-splat/blob/25c6e337761ad2414a6d3377415681d229fe7a3b/examples/rasterization/runner.py)、[参数与优化器初始化](https://github.com/Atlas-Ascend-Fork/gauss-splat/blob/25c6e337761ad2414a6d3377415681d229fe7a3b/examples/rasterization/utils.py)、[渲染反向](https://github.com/Atlas-Ascend-Fork/gauss-splat/blob/25c6e337761ad2414a6d3377415681d229fe7a3b/gauss_splat/ops/calc_render.py)。

数值约定：解析小例子用 FP64，`atol=1e-10, rtol=1e-8`；FP32 简单参数变换以 `atol=1e-6, rtol=1e-5` 为初始标准。NPU 渲染梯度按第 4、6 节的逐算子精度协议验收，不直接套用上述小例子阈值。所有测试先固定随机种子、后端、布局和配置；禁用无关正则、增密与随机相机采样。

#### BP01 无神经网络的解析梯度与三阶段职责（P0，CPU）

- **输入**：可训练 FP64 标量 `c=0.6`，常量 `alpha=0.5,y=0.8`；`C=alpha*c`，`L=(C-y)**2`；SGD 学习率 0.1。这里故意用教学平方损失隔离链式法则，不冒充项目训练损失。
- **步骤**：记录参数；计算损失；调用 `backward()`；记录参数与梯度；执行 `step()`；执行 `zero_grad(set_to_none=True)`。
- **预期结果**：初始 `C=0.3,L=0.25`；反向后 `c.grad=-0.5`，`c` 仍为 0.6；更新后 `c=0.65,L=0.225625`；清梯度后 `.grad is None`。可明确区分求梯度与改参数。

#### BP02 L1、SSIM 权重与架构分支（P0，CPU/NPU）

- **输入**：固定 `[1,32,32,3]` 预测图与真实图，像素在 `[0,1]`；`ssim_lambda` 分别取 0、0.2、1；其他损失关闭。准备相同图和带局部扰动图两组。
- **步骤**：分别记录独立 L1、当前架构 SSIM 与组合 loss；对预测图求梯度；记录 SSIM 实现、窗口和参数。用独立 FP64 滑窗实现按相同 SSIM 定义生成参考，不直接复用被测函数作为唯一 golden。
- **预期结果**：组合值分别为 `L1`、`0.8*L1+0.2*(1-SSIM)`、`1-SSIM`，图像梯度满足相同线性组合；相同图 loss 接近 0。A5 实际走 fused SSIM 窗口 11，另一分支窗口 7；窗口/常数不同不能要求两分支结果相等。

#### BP03 对数尺度和 logit 不透明度的梯度（P0，CPU/NPU）

- **输入**：FP64 `l=log(0.2)`、`o=logit(0.3)`，令 `L=2*exp(l)+3*sigmoid(o)`；另测 `o=-10,0,10`。
- **步骤**：反向计算存储参数梯度；与解析式比较；FP32/NPU 重复，检查有限值。
- **预期结果**：首组 `dL/dl=0.4`，`dL/do=0.63`；极端 logit 按 `3*alpha*(1-alpha)` 验证。不得直接把实际尺度或实际 alpha 的梯度写入存储参数。

#### BP04 渲染器到五类高斯参数的完整反向（P0，NPU）

- **输入**：4 个可见、深度不同的各向异性高斯，非零有效四元数，开启 SH 一阶；64×64 固定相机；全部点离视锥边界、alpha 截断及排序交换位置有余量。用独立参考生成不同于当前渲染结果的目标图；关闭增密和额外损失。
- **步骤**：计算 L1 或平滑的加权图像标量损失；保留中间梯度；反向；对 `means/scales/quats/opacities/sh` 抽样做中心差分，扫描扰动步长；每次扰动确认可见集合、排序和截断分支不变。
- **预期结果**：五类 `.grad` 形状和布局正确、有限，并与独立自动求导/差分参考在约定误差内一致；不是要求所有分量都非零。SH 未激活项、旋转冗余方向等允许零梯度。发生分支变化的样本转入边界测试，不用于光滑梯度结论。

#### BP05 一步 Adam 与梯度 hook（P0，CPU/NPU）

- **输入**：固定五类参数和人工梯度，batch/world_size 均为 1，关闭调度与增密；固定每组 lr、eps、betas；分别准备空状态和已有两步状态。SH 高阶输入梯度设为 1。
- **步骤**：经真实初始化注册 hook；反向后记录实际 `.grad`；把同一组实际梯度交给独立 Adam 公式参考与目标优化器；比较一步更新及一、二阶动量、step；再清梯度。
- **预期结果**：SH 零阶梯度为 1，高阶为 0.05；同一实际梯度驱动的参数与状态按精度协议一致。需分别验收普通 Adam 与 NPU fused Adam；不把 `/20` 梯度缩放简单视为 Adam 参数更新必然缩小 20 倍。清梯度后不发生意外累积。

#### BP06 连续训练与上下文隔离（P0，NPU）

- **输入**：小场景、固定两个不同相机 A/B，固定目标图，增密关闭。
- **步骤**：先执行 A 的前向反向作参考；再构建 A 前向、B 前向、分别反向的多计算图序列；比较 A 梯度；另外按 Runner 正常顺序训练 20 步，逐步记录 loss、梯度、参数变化和有限值。
- **预期结果**：若接口支持多个未反向图，A 梯度不应被 B 的缓存覆盖；若不支持，应明确拒绝或声明约束，不能静默给错梯度。正常序列无跨步残留梯度；在固定小任务和经验证学习率下总体损失改善，不要求每步单调或恢复唯一参数解。

## 7 算法训练与端到端质量

### 7.1 数据与相机

逐项检查 COLMAP 图像名到相机ID的映射；图像resize后 fx/fy/cx/cy同步变化；畸变去除与相机模型一致；c2w/w2c、轴方向和单位一致；场景归一化同时作用于点和相机；保留视角不参与训练。使用已知位置的彩色三维轴或棋盘验证投影，比只看自然图像容易定位错误。

数据清单记录文件哈希、训练/测试索引、分辨率与缩放因子、背景与mask、点云数量、相机模型、曝光处理。用重复文件或几乎相同连续帧划分训练/测试会高估泛化，需记录采样方式。

### 7.2 从固定模型到完整训练

| 用例组 | 做法 | 目的 |
| --- | --- | --- |
| AL01 固定checkpoint | 同一模型和相机分别走参考与目标 | 隔离渲染错误，避免训练补偿掩盖算子误差 |
| AL02 一步更新 | 固定输入/状态，关闭增密，比较loss、梯度、Adam状态和更新后参数 | 精确定位训练链错误 |
| AL03 合成拟合 | 教师渲染少量高斯，多视角拟合，小规模重复 | 检查优化是否有效；不要求恢复唯一参数解 |
| AL04 短训练 | 100—500步，固定相机序列，先关闭再开启增密 | 检查趋势、梯度和数值故障；不要求每步单调下降 |
| AL05 密度事件 | 人为触发clone/split/prune/reset | 每个参数族、动量、计数、ID和hook同步更新 |
| AL06 完整训练 | 固定场景、预算、配置，至少3个seed | 比较最终质量、收敛速度、模型数量与内存 |

#### 7.3.1 统一夹具、执行环境与断言

默认夹具采用 A5 ADC，`scene_scale=1`、`N=4`、SH 一阶、`revised_opacity=False`，参数使用 FP32；`scales=log(实际尺度)`、`opacities=logit(实际不透明度)`。各点位置互异，四元数取 `[1,0,0,0]`，SH 用可追踪的不同值。下表梯度是**缩放与累计平均之后**的统计值，不是原始 `means2d.grad`。

| 标记 | 最大实际尺度 | 平均二维梯度 | 实际不透明度 | 默认事件 |
| --- | --- | --- | --- | --- |
| A | 0.005 | 0.0003 | 0.8 | 复制 |
| B | 0.020 | 0.0003 | 0.8 | 拆分 |
| C | 0.005 | 0 | 0.001 | 删除 |
| D | 0.005 | 0 | 0.8 | 保留 |

设置 `state.grad2d=[0.0003,0.0003,0,0]`、`count=[1,1,1,1]`、`radii=[0.01]*4`。需要直接验证选择规则时调用 `_grow_gs/_prune_gs`；验证调度则调用真实 `step_post_backward`，并控制该次输入梯度，避免不知不觉改变预置平均值。追踪父子关系使用测试侧映射，或用不会被被测操作修改的唯一属性；不要假设存在源码未定义的持久 ID 字段。

- **输入**：ADC 默认时间配置，每次独立重建夹具；step 取 `0,500,599,600,19900,20000,20100`。另设 `pause_refine_after_reset=200` 测 `3000,3100,3200`。
- **步骤**：在真实策略调用中记录 `_grow_gs/_prune_gs/reset_opa` 次数；用 spy 记录调用但保持真实数学逻辑或明确采用只验证调度的桩。
- **预期结果**：默认结构调整仅在本列表的 600、19900 触发；暂停配置下 3000、3100 不增密，3200 增密。3000 仍触发不透明度重置；`step>=20000` 提前返回，不累计、不增密、不重置。每个测试独立，不能让上个用例的清零影响结果。

#### DC03 梯度和尺度边界（P0，选择规则）

- **输入**：梯度阈值 `t=0.0002`；尺度边界为 `0.01*scene_scale`；分别取边界下、等于、上，做 3×3 组合；不透明度统一 0.8。
- **步骤**：预置平均梯度并调用 `_grow_gs`，记录复制和拆分掩码；尺度等号测试令配置阈值等于该输入 `exp(log_scale)` 的实际计算值，避免 log/exp 舍入误判数学等号；其他点用足够分离的扰动，例如相对 1%。
- **预期结果**：`g<=t` 不增密；`g>t` 且尺度 `<=` 边界复制，`>` 边界拆分。默认屏幕分支关闭时两类候选互斥。

#### DC04 可见性累计与平均定义（P0，统计）

- **输入**：某点两次可见，缩放后梯度分别 `(3e-4,0)`、`(-3e-4,0)`；另一点不可见；准备 W/H 不同但归一化后等价的输入组。
- **步骤**：调用 `_update_state` 两次，检查累计值、次数、平均值及半径最大值；再触发一次策略周期。
- **预期结果**：第一点 `grad2d=6e-4,count=2,平均=3e-4`，不能因方向相反抵消成 0；不可见点计数不增加且除零保护有效。原始梯度按代码的 `W/2*n_cameras`、`H/2*n_cameras` 缩放后匹配；周期后 grad/count/radii 清零。

#### DC05 压紧索引映射回原始高斯（P0，统计/NPU 集成）

- **输入**：N=10，原始可见 ID 为 `[2,7,9]`；压紧前三项具有不同梯度和半径，其余填无效值；另准备 `proj_filter` 位图及不满 8 位的尾部。
- **步骤**：分别走显式 `gaussian_ids` 与位图回退路径；回退路径保留该键但置 `None`，以满足当前入口的键存在断言。比较完整长度 10 的累计向量。另故意制造两来源可见集合在中间缺一个 ID 的不一致。
- **预期结果**：正确数据只更新 2、7、9；位图按 little-endian 解码且忽略尾部填充位。中间缺项时不允许把后续梯度错配给另一点；当前“截成共同前缀”的实现需作为缺陷探测项，若仅数量截断掩盖集合错位，应记录失败，不能作为通过条件。

#### DC06 复制的属性与状态（P0，辅助操作）

- **输入**：统一夹具，复制掩码只选 A；完整且带标记的 Adam 状态。
- **步骤**：直接调用 `duplicate()`；检查每类参数、状态、引用；执行一个简单线性损失的反向以检查 hook。
- **预期结果**：N 从 4 到 5，原 4 点保留顺序，新 A 在尾部，属性与父点逐元素相同，无位置扰动；原点动量不变，新点动量为零，step 保留。直接辅助操作复制策略统计；完整周期末才清零。不得要求复制前后渲染图相同。

#### DC07 拆分的几何、顺序与状态（P0，辅助操作）

- **输入**：只选 B，使用各向异性尺度 `(0.02,0.01,0.005)` 与非单位旋转对应的有效四元数；先固定随机张量，再使用固定 seed 的真实随机采样。
- **步骤**：按独立公式计算两个子点 `mu+R*diag(s)*epsilon`；调用 `split()`；检查未选点、子点、参数布局与 Adam 状态。
- **预期结果**：N 从 4 到 5；父 B 消失，未选点保持相对顺序，后面是两个子点；子点位置符合公式，实际尺度为父点 `/1.6`，旋转/SH/默认不透明度继承；新子点动量零，未选点动量保留。固定随机输入测试必须逐项对上，不要求两个偏移相反或体积守恒。

#### DC08 拆分的随机性与可选不透明度规则（P1，辅助操作）

- **输入**：同 DC07；重复足够样本，例如 10000 对偏移；另将父点实际 alpha=0.75，并打开 `revised_opacity=True`。
- **步骤**：同设备同 seed 重跑，检查可复现；多个 seed 统计偏移均值、协方差；对可选模式检查两个子点 alpha。
- **预期结果**：同环境同 seed 可复现；偏移均值在标准误差范围内接近 0，协方差接近 `R*diag(s²)*Rᵀ`，阈值按样本量预设，不能临时调整；可选模式子点 alpha 为 `1-sqrt(1-0.75)=0.5`。跨设备不要求随机样本逐位相同。

#### DC09 低不透明度裁剪及等号边界（P0，辅助操作/策略）

- **输入**：实际 alpha 在 0.005 下方、边界、上方及正常值，梯度为 0，屏幕裁剪关闭。边界可将 `prune_opa` 设置为同一个输入经 sigmoid 后实际计算的值。
- **步骤**：调用 `_prune_gs()`，再直接测试 `remove()` 的掩码筛选；核对全部属性、动量及统计向量。
- **预期结果**：只删除严格小于阈值的点；保留点的顺序、属性、动量保持对应；N 与状态长度同步。不要拿 logit 与 0.005 直接比较。

#### DC10 屏幕尺度分支与架构差异（P0，策略）

- **输入**：低梯度、正常 alpha 的点；归一化半径取 0.04、0.06、0.16；分开测试 grow 与 prune，避免拆分继承统计干扰单一规则。ADC 分别设窗口 0 和 1000，测 step=600、1000。
- **步骤**：记录 `_grow_gs` 的屏幕拆分与 `_prune_gs` 的屏幕删除；Default 开启默认 `screen_prune` 重复裁剪子测试；再准备尺度 0.11、scene_scale=1 的点测 step=3000 与 3100。
- **预期结果**：ADC 默认窗口 0 不使用屏幕分支；窗口 1000 时 step=600 的半径 `>0.05` 可触发拆分、`>0.15` 可触发裁剪，step=1000 不触发这两条规则。Default 默认删除半径 `>0.15` 的点，三维尺寸裁剪仅在 `step>3000` 生效；ADC 不因声明了 `prune_scale3d` 就自动执行该规则。

#### DC11 完整事件顺序与点数守恒式（P0，策略）

- **输入**：统一四点夹具，step=600，上限足够大，屏幕分支关闭。
- **步骤**：记录真实 `duplicate→split→remove` 调用及父子映射；比较每一步 N；完成后检查统计清零。
- **预期结果**：4 → 5（复制 A）→ 6（B 替换成两点）→ 5（删 C）；新复制 A 不在同轮再拆分；最终保留 D、父 A、A 副本和 B 的两个子点。一般满足 `N_after=N_before+D+S-P-Q`，S 是拆分父点数、P 是普通删除数、Q 是超限删除数，三者不得混淆。

#### DC12 数量上限与峰值内存（P0，策略/NPU）

- **输入**：先用 `cap_max=5` 的小场景，构造增密后 N=8 且各点 alpha 不同；另在实际 NPU 上按显存预算逐级扩大到接近配置上限，保留安全余量。
- **步骤**：记录增密后、普通裁剪后、上限裁剪后的 N；记录各阶段峰值设备内存；增加 alpha 相等的并列组测试。
- **预期结果**：小场景移除最低 alpha 的超额 3 点，最终 N=5；并列情况下只要求满足数量和阈值集合，不强求未规定的稳定顺序。必须记录 N 曾达到 8，不能宣称上限约束中间峰值。接近容量时出现不可恢复 OOM 视为容量/保护缺陷；`empty_cache()` 不替代峰值控制。

#### DC13 不透明度重置与优化器状态（P0，策略/辅助操作）

- **输入**：alpha `[0.2,0.5,0.9]`，对应非零 Adam 动量，其他参数也有状态；ADC 默认 reset_value=0.5，step=3000；另测 0、2999、20000。
- **步骤**：调用 `reset_opa()` 检查数学变换，再通过策略调度检查时机；记录同轮 grow/prune/reset 顺序。
- **预期结果**：alpha 变为 `[0.2,0.5,0.5]`，N 不变；仅不透明度动量清零，step 保留，其他参数/状态不变。默认 3000 先结构调整后重置；0、2999、20000 不触发重置。Default reset_value=0.1 时应另用其预期值，不能套用 ADC。

#### DC14 布局、参数引用和 SH hook（P0，辅助操作/NPU）

- **输入**：同一参数集合分别转为 N-first 与通道优先：means/scales `[3,N]`、quats `[4,N]`、SH `[K,3,N]`、opacity `[N]`；固定拆分随机输入。
- **步骤**：用受支持的辅助操作分别执行复制、拆分、删除；统一转回 N-first 比较；反复组合事件后，用 SH 求和构造反向。
- **预期结果**：两布局逻辑结果一致，沿 N 维操作；所有 optimizer 引用当前 Parameter，旧对象不残留；SH 零阶梯度为 1，高阶为 0.05，不能丢 hook 变成 1，也不能重复缩放成 0.0025。

#### DC15 替换参数对当前轮梯度的影响（P0，行为确认与缺陷探测）

- **输入**：完整已初始化的 Adam 状态，所有参数先完成一次反向；分组测试无结构事件、复制、拆分、删除、仅 opacity reset。
- **步骤**：在 backward 后、策略后、optimizer.step 后分别保存参数对象、`.grad`、参数数值及动量；随后再运行一个正常前向反向更新。
- **预期结果（当前实现行为）**：无事件组保留梯度并更新；重建的 Parameter 没有迁移旧 `.grad`，标准优化器可能跳过其本轮更新；仅 reset 时主要影响 opacity 参数。下一轮应重新获得梯度并更新。NPU fused Adam 是否同样跳过须实测。
- **验收处理**：这是行为特征测试，不把“丢失当前梯度”自动认定为合理设计。若要求结构调整轮仍更新保留点，则应另设期望为“按保留索引迁移梯度”，当前实现不满足时登记缺陷；不能为了通过测试而默许更新约定变化。

#### DC16 空集合、零可见与无状态优化器（P0，辅助操作/集成）

- **输入**：N=1 和 N=4；空选择掩码、所有点零可见、全删掩码；优化器分别有/无已有状态。
- **步骤**：逐个调用辅助操作和完整策略；对全删后的 N=0 再调用下一轮渲染与反向。
- **预期结果**：无候选的策略路径不应无故增加点；零可见时平均梯度无 NaN；无初始化状态时新状态应可被下一次优化正确建立。全删后辅助张量应一致为空。若渲染不支持 N=0，集成必须给出清晰拒绝/保护策略，不能内核越界或挂起。当前是否具备该保护须实测记录，不预设已支持。

#### DC17 无效配置与异常数值（P0，健壮性目标）

- **输入**：`refine_every=0`、`reset_every=0`、ADC cap 为负数、reset_value 不在 `(0,1)`；梯度/尺度/opacity 包含 NaN、Inf；极端 log-scale、零四元数。
- **步骤**：分别执行配置校验、统计、选择和拆分；记录异常出现层级、错误消息及是否已修改参数；覆盖训练步数缩放把周期截成 0 的情况。
- **预期结果（目标契约）**：无效输入在不可逆的模型修改前明确拒绝或采取已文档化的有限值处理；不允许除零、隐式 NaN 掩码或带损坏参数进入内核。源码未必已有这些检查，缺失应登记缺陷，不能把当前异常堆栈当作合格行为。ADC cap=0 与 Default cap=0 的语义也应明确区分，不能未经定义就视为统一“关闭上限”。

#### DC18 连续事件后的端到端训练（P0，NPU）

- **输入**：小型多视角合成场景；将测试策略窗口设为 start=0、every=2、reset_every=6、stop=20，记录为测试专用配置；准备关闭增密的对照组。
- **步骤**：运行至少 24 步，捕获每个事件前后 N、参数/状态形状、梯度、loss、峰值内存；保存结构变化后的参数并重载渲染；分别验证普通 Adam 与实际架构的 fused Adam。
- **预期结果**：连续事件无对象悬挂、维度错位、陈旧 ID 或非有限数；step>=20 不再进行策略修改但常规训练继续；重载同一参数和相机的渲染一致。增密后单步 loss 可上升，不要求点数越多画质必然越好；长期质量用固定预算、多 seed 的独立验证视角评估，不以训练损失替代验收。

#### 7.3.2 执行记录与判定方式

每条记录至少包含：用例 ID、代码提交、实际策略字段、架构/构建、布局、种子、输入参数快照、父子映射/选择掩码、事件前后 N、参数与动量误差、峰值内存、结果及缺陷链接。CPU 参考、NPU 实测和静态审查分别标记；尚未执行保持“待执行”。

优先执行 P0 的规则、索引和状态测试，再做 NPU 事件后继续训练，最后扩大规模。DC05 的回退索引错配、DC15 的梯度迁移约定、DC16 的空模型、DC17 的输入保护属于需要明确暴露的风险，不能通过放宽数值容差绕过。

### 7.4 场景矩阵与指标

| 场景桶 | 建议数据/构造 | 观察重点 |
| --- | --- | --- |
| 室内有界 | bonsai、room类公开场景 | 遮挡、纹理、细杆和曝光 |
| 室外无界 | garden、bicycle类公开场景 | 深度跨度、远景、小高斯和植被 |
| 薄结构与高频 | 自制细栅栏、文字、斜线 | 断裂、锯齿、细节丢失 |
| 高深度复杂度 | 多层半透明遮挡合成场景 | 早停、梯度与排序 |
| 低纹理/反光/运动干扰 | 单独标注挑战集 | 识别算法能力边界，避免混为kernel数值缺陷 |
| 多尺度与连续相机 | 焦距变化、推拉、环绕、不同分辨率 | 闪烁、突然跳变和采样伪影 |

公开场景使用项目下载脚本和原始数据划分，实际选择以可用数据为准。Mip-Splatting 的采样率分析支持将焦距/距离变化纳入专项测试，不能只测固定训练分辨率。[Mip-Splatting](https://niujinshuchong.github.io/mip-splatting/)

PSNR定义为 $10\log_{10}(MAX^2/MSE)$；统一 MAX和RGB范围。SSIM固定窗口、sigma、padding与reduction。LPIPS固定backbone、模型版本、输入归一化；本地有alex/vgg配置，混用会失去可比性。指标必须在相同保留视角、尺寸、mask和clamp约定上计算。

报告每场景/每seed/每视角分布，包含均值、中位数、最差视角、置信区间或范围；给出时间到目标质量、N增长和loss曲线。连续视角展示并检查局部伪影，不能用相邻帧简单像素差衡量闪烁，因为正常相机运动本来会改变图像；可用相同轨迹的基线对照或几何配准后的残差。

初始画质告警可设为同配置配对实验中PSNR下降>0.2 dB、SSIM下降>0.005或LPIPS上升>0.01，**仅作为调查起点**，需结合基线seed波动冻结业务门槛；任何明显结构性伪影即使平均值合格也要单独调查。像素级等价优化应先过L1/L2数值门禁，不靠这类宽松画质门槛放行。

### 7.5 保存文件与恢复训练不是一回事

当前 `runner.py` 保存 `{step,splats}`，位置在 `optimizer.step()` 之前，eval在更新之后。因此同一步标签的文件与内存eval可能不是同一组参数。AL07必须抓取保存瞬间的模型并对照相同SH阶数、相机与配置。

文件不包含完整优化器、调度器、随机数及策略状态，当前 `--ckpt` 用于加载评估，不应宣传为精确断点续训。若产品未来要求恢复训练，应额外保存上述状态，并比较连续训练与中断恢复后的下一步loss、参数、动量及后续曲线。

### 7.6 深度与SLAM扩展

当前深度链先统一语义，再增加稀疏深度监督、单位/尺度和相机轴向深度测试。不要将光线距离与z、累积量与期望量互比。若扩展到SLAM，另测ATE/RPE、尺度对齐条件、丢跟踪恢复、地图漂移和实时性；这些不由RGB PSNR替代。Gaussian Splatting SLAM本身增加了相机跟踪和几何约束，属于系统扩展。[论文](https://arxiv.org/abs/2312.06741)
## 8 融合优化与迁移测试

### 8.1 等价优化与算法近似分开验收

等价优化如布局转换、流水重叠、缓存、融合和负载调度，应在相同输入与语义下满足数值误差预算。更激进的过滤、早停或降低精度可能改变算法，除前向误差还需要固定模型画质、梯度影响、重训质量和最差场景测试。

消融顺序建议：基础路径→协方差融合→筛选压缩→精确相交→调度→渲染剪枝→SSIM/Adam融合，每次只改变一项。源码没有公开开关时，在隔离测试适配器或专项构建中做单项替换，记录patch和产物哈希，不在命令中虚构现成flag。

每一步留存 means2d、conic、有效ID、配对集合、排序ID、RGB/深度、参数梯度，找到“第一个发生差异的阶段”。单看最终图像很难判断是几何、索引、数值还是训练目标变了。

### 8.2 R到G及架构迁移

| 迁移项 | 必做适配和比较 |
| --- | --- |
| 包名与接口 | 分别构建环境，禁止加载到错误扩展；核对导出符号 |
| N-first↔channel-first | 用非对称编码数据，逐元素检查往返；N=3也要防形状偶合误判 |
| sh0/shN↔sh | 拼接维度、零阶偏置、高阶学习率与hook保留 |
| 协方差与投影 | 对齐eps、相机模型、near/far、阈值和dtype |
| 深度 | 明确z/1z、是否归一化和深度loss转换，禁止直接比同名字段 |
| 训练loss | 将SSIM窗口与sigma统一后才能进行硬件等价比较 |
| 缓存与多相机 | G已有新逻辑，按新代码验收，不能照搬R风险清单 |
| 保存加载 | 旧schema到新schema，再到运行布局，检查图像和梯度hook |

尤其注意：当前G训练中A2/A3深度loss对输出再取倒数，而A5直接使用输出；主渲染链两者均传逆深度属性。应通过单高斯深度监督例确认意图，不能先把这类差异归入允许精度误差。

### 8.3 测试自身的测试

对参考或被测输出故意制造一次错误：交换两个ID而保持count、漏一个Tile、四元数梯度乘2、将一步optimizer更新跳过、返回上一帧means2d梯度。测试必须失败。若不失败，说明断言未覆盖真实风险。

不要为了当前实现过测试而反向修改golden；golden更新要同时提交语义变更、旧新差异和独立验证。
## 9 性能容量与稳定性

### 9.1 性能计时协议

先通过正确性测试，再冻结硬件、版本、构建模式、输入、精度、阈值、图像大小、N、T、L和可见比例。区分kernel时间、完整渲染时间、训练step与全程wall time。使用目标版本支持的NPU事件/profiler；完整wall time在起止显式同步，不把异步提交耗时当成设备完成耗时。

预热20次、正式至少100次、重复3轮可作为微基准起点，报告样本数、median/P90/P99和波动。若需要稳定P99，增加至足够样本（例如1000次以上）并报告置信度；长耗时训练以独立重复运行统计。吞吐测试不要每个kernel都全局同步，定位阶段再加同步。

| 维度 | 计时边界 | 额外记录 |
| --- | --- | --- |
| 单算子 | 准备好输入到完成输出，分配是否包含单列 | tiling key、workspace、core数、launch数 |
| 稳态一帧 | 激活/求色到最终图像 | CPU调度、设备往返、排序、裁剪都计入 |
| 首帧 | 创建实例、首次分配与调用 | 与稳态分开 |
| 一步训练 | 数据就绪至optimizer完成 | forward/backward/densify/optimizer分项 |
| 完整训练 | 数据加载、训练、评估、保存分项wall time | time-to-quality、最终N、质量 |
| 内存 | allocated/reserved/峰值及缓存 | 在设备同步后读数，注明是否重置峰值 |

`get_render_schedule_cpp` 前有 `.cpu()`，后有 `.npu()`，还有 `.item()`同步。这些可能影响小场景端到端性能，不能只看设备混合kernel。A5的SIMT、Cube/Vector利用率、搬运、流水与核拖尾用对应平台profiler定位，不照搬CUDA指标名称。

### 9.2 从C++分配推导容量

当前 `FlashGaussianBuildMask.cpp` 为depth和ID各分配 `[B,C,T,N]` FP32，gather workspace为 `[V,20,N]` FP32。V在arch22为48，A5按实际设备查询，查询失败回退64。因此这三个数组的理论字节数为：

$$M\approx8BCTN+80VN.$$

示例B=C=1、N=1,000,000、1920×1080、tile=32，T=60×34=2040。仅两张稠密表为16.32 GB；V=48时加gather约20.16 GB，V=64时约21.44 GB，均为十进制GB。**这是静态分配估算，不是实测峰值**，还没有模型、梯度、Adam、排序和渲染中间量。

高层C>1当前逐相机执行，不能机械地把上述单次kernel公式中的C设置为高层相机总数来估算完整峰值；还要分析各视角autograd保存张量和临时缓冲的存活时间。

筛选后的容量仍用N，因此实际配对少不代表上述分配小。压力测试先算容量、预留系统和workspace余量，再递增规模；OOM应可定位并可恢复，不盲目直接运行百万高斯高分辨率。

中间ID采用FP32，超过$2^{24}$不能精确表示所有整数；tile offset及调度有int32路径。通过主机算术和小规模边界注入验证溢出/精确性，不必为了触发边界分配超大数组。实际限制应在输入校验层提前暴露。

### 9.3 性能压力矩阵

| 扫描轴 | 样本 | 期望观察 |
| --- | --- | --- |
| 高斯数 | 1万、10万、按容量递增 | 延迟与内存趋势，分块台阶 |

固定基线下median退化>5%、P99退化>10%或峰值内存显著增长可作为初始告警，先测环境噪声再冻结发布标准。性能收益必须同时给出画质与梯度检查，不能靠少渲染高斯获得“免费加速”。

### 9.4 稳定性与兼容

运行动态尺寸序列64×64→33×65→64×64，以及同padding尺寸但不同裁剪尺寸；改变N、相机数和设备，与新实例结果比较。几何缓存已有key不代表所有下游状态正确，仍需集成检查。

执行交替forward/backward、多个实例、同实例多图在途、不同stream、非0逻辑设备；记录buffer生命周期和同步。长稳可先1小时冒烟、再按业务8—24小时训练/渲染，观察内存是否平台化、输出是否漂移、异常后实例是否能继续使用。此时长是建议资源计划。

干净环境构建wheel、从仓库外导入、逐个符号调用；分别覆盖每个声明架构和配套软件组合。对不支持架构/输入明确拒绝。官方版本配套在实际执行时再次核对并冻结，不能把本次README版本号作为永久有效环境要求。
### 9.5 Profiling 算子名称白名单与实际后端覆盖校验

**PF01 名称映射完整性与漏统计检测（P0，待执行）**

目的：确保性能汇总没有因算子更名、架构切换或融合路径变化，静默遗漏当前实际执行的目标算子。该项检验的是 profiling 统计程序的正确性，不是设备算子数值正确性。

当前源码依据：[run_msprof_train.py](https://github.com/Atlas-Ascend-Fork/gauss-splat/blob/25c6e337761ad2414a6d3377415681d229fe7a3b/examples/run_msprof_train.py) 的 `FWD_OPS/BWD_OPS/OP_NAMES` 与 `parse_op_summary()`。解析器按 `target in op_name` 做子串匹配，只汇总白名单项；未匹配行不会进入结果，缺失项返回 `None`。它还逐算子剔除部分前序记录作为 warmup，因此覆盖核对应在这一步之前完成，不能用过滤后的平均值检查原始记录完整性。

静态审查发现：白名单包含 `CalcRenderSimtFwd/CalcRenderSimtBwd`，而当前 A5 桥接调用的是 `aclnnCalcRenderFwdClipLastids/aclnnCalcRenderBwdClipLastids`，见 [CalcRenderClipLastids.cpp](https://github.com/Atlas-Ascend-Fork/gauss-splat/blob/25c6e337761ad2414a6d3377415681d229fe7a3b/gauss_splat/csrc/CalcRenderClipLastids.cpp)。这是需要检查的名称映射风险，**不是已经证明真实 profiler 输出必然漏项**：API 名称与设备记录名称不一定相同，必须用当前构建的实际 trace 确认。

**输入**

- 当前提交、实际加载的扩展路径、设备架构及 CANN/profiler 版本；分别准备可用的 A5 与 A2/A3 构建，不具备的环境标记待执行。
- 固定 checkpoint、相机、分辨率、SH 阶数、前向/前后向模式，以及实际融合和深度配置。基于执行路径列出本次应出现的逻辑算子，不能要求未启用的路径也出现。
- 同一次有效采集窗口内的完整 `op_summary` 和关联时间线，保留原始 Op Name、Op Type、Task Duration、设备/流/任务及迭代标识等实际可用字段。不能只输入已经按名称筛选的 CSV。
- 解析器夹具：正常匹配名、已确认别名、未知名、缺失目标名、会命中两个候选规则的名称，以及缺少/无法解析 duration 的行。夹具使用独立的唯一记录编号和已知时长。

**步骤**

1. 冻结采集窗口，排除初始化、评估、保存等非目标阶段；先从未过滤原始记录列出全部实际算子名称、调用次数及设备任务耗时。
2. 通过时间线关联与当前源码，建立“逻辑操作 → 实际后端 → 实际 profiler 名称”的映射。重点核对 clip_lastids、clip_gsids、SIMT 名称与前反向配对；不凭 `aclnn` 前缀判断是 Host 事件还是 Device 任务。
3. 对照白名单逐条分类：应纳入的 3DGS 目标任务、显式排除的通用/辅助任务、未识别任务。记录排除理由；通用张量算子若不属于该报告范围可以排除，但不能把报告称为全部设备计算耗时。
4. 回放原始 CSV 并记录匹配过程；检查应纳入任务是否漏匹配或重复匹配。若一个逻辑操作对应多个设备任务，保留全部关联任务；若融合改变粒度，记录融合映射，不能强求一对一。
5. 用解析器夹具验证新名称、未知名称、双重子串命中和异常字段；将有效记录的条数、次数和耗时与独立的按记录编号汇总结果比较。
6. 在覆盖核对通过后再应用明确的 warmup/有效迭代筛选，并比较最终统计。若使用现有“逐算子剔除若干条记录”逻辑，检查不同算子是否落在不同迭代窗口；不能默认等同于统一预热迭代。

**预期结果**

- 有效窗口内每条应纳入的设备任务都映射到目标统计，且在同一份汇总中只计一次；缺失目标、未识别名称、异常字段和多重命中必须显式报告，不能静默跳过后给出“完整”结论。
- 未执行的可选算子标为“不适用/未执行”；应执行但未找到的算子标为“缺失待查”。不能把 `None` 或漏项解释为 0 微秒，也不能把“不适用”自动算作采集失败。
- 筛选前后满足可核对的记录账目：原始有效设备记录 = 纳入记录 + 明确排除记录 + 未识别记录；同一范围内时长之和同样对应。存在不可解析时长的记录应单列，不能混入“有效时长完整”的结论。
- 更新名称映射后，已确认的别名被正确识别；未知记录仍保留并报警；两条子串规则命中同一记录时，不重复计数。当前脚本未满足的行为记录为统计工具缺陷，不视为设备内核缺陷。
- 按同一采集窗口生成匹配覆盖表：逻辑算子、架构、实际名称、原始次数、纳入次数、总设备耗时、排除/缺失理由。汇总设备任务耗时不等于端到端延迟，不与嵌套 Host/ACLNN API 耗时直接相加。

**证据与验收**：保存原始 trace/CSV、运行配置、名称映射版本、未匹配及重复匹配清单、夹具期望值与解析结果。所有应纳入任务无漏计、无重复计数，异常记录已显式处理，才允许发布该范围的性能汇总。本次只新增测试设计与静态风险说明，未运行 NPU profiling，也未修改统计脚本。

不需要先等待全套测试框架建成才发现问题：G0的小例往往能快速排除错误参考和无效配置。资源不足时优先P0和真实小场景；被跳过的必测平台与功能应标记未验证，不能算通过。

### 11.5 发布验收

- 已声明范围内所有P0通过，未验证能力明确列出；收集失败、skip不能计作通过。
